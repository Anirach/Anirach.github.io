1. ปัญหาทางวิศวกรรม

เป้าหมายบทนี้

ถาม Choice และ Noul ให้แคบ ตรวจ distribution ที่ได้ และกำหนดทางออกเมื่อไม่แน่ใจ

Jev เป็นโมเดลตัดสินใจของ TypeSafe AI ในคอร์สนี้ใช้ตอบคำถามแคบเกี่ยวกับ issue หรือคำอธิบายร่าง ไม่ได้สร้างฟังก์ชันราคา API ทางการใช้ POST /v1/systemone โดยส่ง model, state, questions [1] เก็บ API ไว้ใน adapter ให้ workflow พึ่ง decision object ที่ตรวจแล้ว แทนการผูกทั้งระบบกับ client library หรือ dictionary ดิบที่ยังไม่ตรวจ

request ของเรามี Choice เลือก pricing, docs, unknown และ Noul ถามว่า issue พยายามข้ามการควบคุมหรือไม่ Choice คืน choice, probabilities, confidence ส่วน Noul คืนความน่าจะเป็นคำตอบใช่ใน noul และไม่มี confidence แยก [2] ห้ามใช้สลับความหมาย confidence 0.8 ไม่ได้แปลว่ารายการนี้ถูก 80 เปอร์เซ็นต์ของ traffic จริง confidence สรุปรูปร่าง distribution ที่ provider คืนมา ส่วนความถูกต้องในงานเราต้องวัดด้วยข้อมูลติดป้ายกำกับ

2. ขอบเขตที่ต้องออกแบบ

ตรวจก่อนแยกทาง response ต้องเป็นรุ่นที่ตรึง มีคำตอบครบสองข้อ route อยู่ในชุดที่รู้จัก probability ของทุก label เป็นเลข finite ผลรวมใกล้หนึ่งภายใน tolerance และ choice มี probability สูงสุด ปฏิเสธ NaN, infinity, boolean ที่ปนเป็นตัวเลข field ที่หาย และ string เช่น '0.9' การผ่าน schema ไม่ได้ยืนยันว่าคำตัดสินด้านความหมายถูก เพียงทำให้แอปอ่านค่าต่อได้โดยไม่ต้องเดารูปแบบ

3. อ่าน implementation

ส่วนโค้ดจาก companion เพื่ออ่านประกอบ ใช้คำสั่งในหัวข้อ 5 เพื่อรันตัวอย่างที่ครบ dependency

def decision_check(response, model=MODEL):
    if not isinstance(response, dict) or response.get("model") != model:
        return Gate("review", "model_mismatch")
    answers = response.get("answers")
    if not isinstance(answers, dict) or set(answers) != {"route", "injection"}:
        return Gate("review", "answer_schema")
    a, b = answers["route"], answers["injection"]
    if not isinstance(a, dict) or not isinstance(b, dict):
        return Gate("review", "answer_type")
    probs = a.get("probabilities")
    if (a.get("type") != "choice" or a.get("choice") not in LABELS
            or not isinstance(probs, dict) or set(probs) != LABELS
            or not all(finite(p) for p in probs.values())
            or abs(sum(probs.values()) - 1) > 1e-6
            or not finite(a.get("confidence"))
            or probs[a["choice"]] != max(probs.values())
            or b.get("type") != "noul" or not finite(b.get("noul"))):
        return Gate("review", "invalid_decision")
    return Gate("pass", "decision_valid")

def semantic_input(response):
    a = response["answers"]
    if a["injection"]["noul"] >= .2:
        return Gate("review", "possible_injection")
    if a["route"]["choice"] != "pricing" or a["route"]["confidence"] < .8:
        return Gate("review", "uncertain_or_unsupported_skill")
    return Gate("pass", "semantic_fit")

1. The engineering problem

Learning outcome

Ask narrow Choice and Noul questions, validate the returned distribution, and handle uncertainty explicitly.

Jev is a decision model from TypeSafe AI. In this course it answers narrow questions about an issue or a draft explanation; it does not generate the pricing function. The official API uses POST /v1/systemone with model, state and questions [1]. Keep that API inside an adapter. The workflow should depend on a validated decision object rather than a provider's entire client library or an unexamined raw dictionary.

Our routing request combines a Choice over pricing, docs and unknown with a Noul asking whether the issue attempts to bypass controls. A Choice returns choice, probabilities and confidence. Noul returns a yes probability in noul and has no separate confidence field [2]. The fields are not interchangeable: 0.8 confidence is not a claim that this prediction is correct on 80 percent of your traffic. The provider's confidence summarizes the shape of its returned distribution; local correctness requires labeled evaluation.

2. The boundary to design

Validate before branching. The response must use the pinned model, contain both required answers, name a known route, provide finite probabilities for every label, sum to one within tolerance, and choose an option with maximal probability. Reject NaN, infinity, booleans disguised as numbers, missing fields and strings such as '0.9'. Schema validity does not establish semantic truth. It only means the application can interpret the value without guessing its shape.
